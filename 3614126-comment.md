Thanks for the report, the diagnosis and the patch. All correct. `CacheTagsPurgeInterface` was added in core 11.2, and since PHP resolves an `implements` clause at class-compile time, the invalidator was fatal to autoload on Drupal 10. Reproduced on 10.5.6.

I committed a different fix, though. Core dispatches that purge on an `instanceof CacheTagsPurgeInterface` check, so removing the interface fixes Drupal 10 but silently disables `purge_everything_on_flush` on 11.2+. The setting stays on the form and stops doing anything. The purge now runs from `hook_cache_flush()`, which `drupal_flush_all_caches()` invokes at the same point on Drupal 10, 11 and 12 alike, so one code path covers every supported version. `purge()` is renamed to `purgeEverythingOnFlush()`; behavior and guards are unchanged.

Also added a kernel test that asserts a real flush reaches the zone purge, and turned on CI against Drupal 10: it was never tested, which is how this shipped green.

Released as **3.1.3**. If you applied the patch, replace it with the release, as the patch turns the feature off on Drupal 11.2+.

Credit to @mrsoundmaurix for the report and patch, and @cameron prince for confirming it. Marking fixed.
