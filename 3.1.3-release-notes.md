# Cloudflare Purge 3.1.3

**Critical fix for Drupal 10. Any Drupal 10 site on 3.1.2 should update now.**

## 3.1.2 vs 3.1.3

| | 3.1.2 | 3.1.3 |
|---|---|---|
| Drupal 10 | Fatal — `Interface "Drupal\Core\Cache\CacheTagsPurgeInterface" not found`, white screen on cache rebuild | Works |
| Drupal 11.2+ / 12 | Works | Works |
| Drupal 11.0–11.1 | Fatal (same cause) | Works |
| "Purge everything on cache flush" | Drupal 11.2+ only | Every supported core version |
| Flush hook used | `CacheTagsPurgeInterface::purge()` (core 11.2+ only) | `hook_cache_flush()` (Drupal 10, 11 and 12) |
| Core versions tested in CI | Current only | Current, previous minor, previous major (Drupal 10) |
| Flush purge test | Called the method directly | Kernel test drives a real flush through the container |

## What changed

- **Fixed the Drupal 10 fatal** ([#3614126](https://www.drupal.org/project/cloudflare_purge/issues/3614126)). `CloudflareCacheTagInvalidator` implemented a core interface that only exists in Drupal 11.2+. PHP resolves an `implements` clause when the class is loaded, and the class is a cache-tag invalidator loaded on any tag invalidation — so the site died on cache rebuild rather than losing a feature.
- **Moved the flush purge to `hook_cache_flush()`.** `drupal_flush_all_caches()` invokes it at the same point on Drupal 10, 11 and 12, so one code path serves every supported version.
- **Renamed** `CloudflareCacheTagInvalidator::purge()` to `purgeEverythingOnFlush()`, as it is no longer a core interface method. Behaviour, guards and the opt-in setting are unchanged.
- **Added a kernel test** that asserts a cache flush actually reaches the Cloudflare zone purge. The old unit test called the method directly, so it proved the method worked but never that anything called it.
- **Turned on CI for previous major and previous minor core.** Drupal 10 had never been tested, which is how 3.1.2 shipped with a green pipeline.
- **Fixed two pre-existing PHPUnit 9 incompatibilities** in the test suite, exposed once the Drupal 10 job ran: data providers declared only as PHP attributes, and a PHPUnit 10+ only `<source>` element in `phpunit.xml`.

## Upgrading

- No configuration changes. Nothing to do after updating.
- **If you applied the interim patch from #3614126, replace it with this release.** That patch clears the Drupal 10 fatal but silently disables `purge_everything_on_flush` on Drupal 11.2+ — the checkbox stays on the form and stops working.
- Drupal 11 and 12 sites were never hit by the fatal, but should still update.

## Verified

- Every class loads clean under a Drupal 10.5.6 autoloader (3.1.2 fatals).
- Full suite green on Drupal 10.1.7 / PHPUnit 9.6, Drupal 11.4.5 / PHPUnit 11.5, Drupal 12.0-dev / PHPUnit 12.5.
